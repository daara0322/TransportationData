# 저상 여부 연결 결과와 남은 과제

> 당시 검증 과정을 보관한 메모다. 현재 결과·범위는 [최종 분석 범위](../scope-decision.md)와 [후보 공동 선정](../candidate-facility-comparison.md)을 따른다. 아래의 진행 상태는 작성 당시 기준이다.

2026-10-17 작성. 이 문서는 최종 정책 순위가 아니라 데이터 연결 가능성을 확인한 기록이다.

## 무엇을 연결했나

T-Data 운행통계의 2026-10-13~15 기록을 서울 버스위치 API의 2026-10-17 16:16:39~16:18:04(KST) 응답과 연결했다. 연결키는 노선 ID와 차량 ID의 조합이다. API의 busType 0은 일반, 1은 저상으로 구분했다. 연료는 이 항목으로 추정하지 않았다.

노선 후보는 1월 인가현황의 노선번호와 운행통계의 노선명이 정확히 일치하고 서울 차량번호가 관측된 경우로 뽑았다. 총 393개 ID다. 공식 노선 ID 마스터를 확보한 것은 아니므로 서울 전체 노선을 확정한 목록으로 사용하지 않는다. 인가현황과 운행자료 사이에는 9개월 차이도 있다.

## 실제 집계

| 항목 | 결과 |
|---|---:|
| 요청 노선 후보 | 393개 |
| 차량 기록을 받은 후보 | 350개 |
| 데이터 없음 응답 | 43개 |
| 요청 오류 | 0개 |
| API 차량 위치 기록 | 4,433건 |
| 후보 노선의 과거 운행 기록 | 116,341행 |
| 과거 차량·노선 조합 | 7,251개 |
| 현재 저상 분류를 연결한 조합 | 4,431개 |
| 연결된 저상 조합 | 3,590개 |
| 연결된 일반 조합 | 841개 |
| 미분류 조합 | 2,820개 |
| 분류 연결률 | 61.1% |

API 기록 중 2건은 같은 차량·노선 조합이 과거 3일 자료에서 발견되지 않았다. 분류가 충돌한 조합은 0개다. 위 조합 수는 서울 전체 고유 차량 수가 아니다. 같은 차량이 다른 노선을 운행하면 별도 조합이 된다.

현재 분류가 과거 운행일에도 유효했는지는 별도로 확인해야 한다. 토요일 오후 한 시점의 관측으로 야간·휴차 차량이 빠질 수 있다. 데이터 없음은 차량 0대나 저상 0대를 뜻하지 않는다. 미분류를 일반버스로 대체하거나, 61.1%의 연결 표본으로 전체 보급률을 추정하지 않는다.

예를 들어 104번은 과거 차량·노선 조합 24개 가운데 이번 응답으로 18개를 분류했고 저상 2개, 일반 16개였다. 나머지 6개가 미확인이므로 이 노선의 전체 저상 비율을 2/24로 발표할 수 없다. 관측된 일반 차량이 많다는 이유만으로 전환 우선순위가 높다고 결론 내리지 않는다. 차량규격, 노선 유형, 도로·충전 제약, 연료, 수요를 함께 확인해야 한다.

최종 연결 결과는 `outputs/public/lowfloor_linkage_authorization.json`에 있다. 초기 실험용 요약은 최종 결과와 중복돼 정리했다. 차량 ID와 위치가 포함된 원본 응답은 Git 제외 폴더에 보관한다.

## 주제에 도움이 되는 공식 통계

[서울시 버스 현황](https://news.seoul.go.kr/traffic/archives/300)의 2026년 1월 마을버스 표에는 전기 397대, 그중 저상 334대가 제시돼 있다. 표상 차이는 63대, 전기버스의 약 15.9%다. 친환경 차량 보급과 저상 접근성을 각각 확인해야 한다는 배경 근거로 쓸 수 있다. 마을버스 총량 통계를 시내버스 개별 노선이나 10월의 차량 특성으로 옮겨 적용하지 않는다.

같은 페이지의 시내버스 저상 현황은 유형별 표 5,438대와 누적 도입 표 5,439대로 1대 차이가 난다. 기준 확인 전에는 둘을 임의로 일치시키지 않는다.

## 탄소계산을 아직 하지 않은 이유

차량별 연료를 확보하지 못했다. [공공데이터포털의 시내버스 연료별 차량수](https://www.data.go.kr/data/15113221/fileData.do)는 찾았지만 2023-04-04 기준의 회사별 집계이며, 회사명과 CNG·전기·수소 대수만 제공한다. 이번 2026년 차량별 운행 이력에 연료를 직접 붙일 수 있는 자료가 아니다. 현재 명세를 확인한 단계이며 파일을 확보한 자료로 기록하지 않았다.

운행거리의 단위와 음수 기록의 의미도 아직 확정하지 못했다. 따라서 km당 배출계수를 적용한 탄소감축량과 차량 교체 순위를 산출하지 않았다. 자료 확보와 단위 검증이 끝나야 같은 교체 대수에서 탄소 중심·접근성 중심·공동 고려안을 비교할 수 있다.

## 다음 작업 순서

1. 공식 노선 ID 마스터와 후보 목록을 대조한다. 변경·폐선·맞춤·심야 등 누락 원인을 분리한다.
2. 다른 시간대에 다시 관측할 경우 기존 조합의 분류 연결률이 얼마나 늘어나는지 확인한다. 호출 한도를 확인한 뒤 필요한 수집만 한다.
3. 거리 정의와 차량·노선별 연료 자료를 확인한다. 확보하지 못하면 차량별 실측 감축량 분석으로 발표하지 않고 가능한 분석 범위를 조정한다.
4. 교통약자 수요·정류장 경로와 저상 공급을 연결한다. 일반버스가 많다는 사실과 교통약자의 이용 기회가 부족하다는 주장을 구분한다.

## 재현

표준 라이브러리만으로 API 수집, 연결 집계와 검증을 실행할 수 있다. `.env.example`을 참고해 로컬 `.env`를 준비한다. 실제 키를 문서·노트북·명령 인자에 넣지 않는다.

```powershell
python -m unittest discover -s tests -v
# 새 수집은 최대 40개 노선 ID를 담은 로컬 JSON을 별도로 준비한다.
python -m src.link_positions --operations data/raw/tdata_vehicle_operations.csv --snapshot data/raw/bus_positions/authorization_snapshot.json --output outputs/public/lowfloor_linkage_authorization.json
```

수집 명령은 새로운 시점의 응답을 만든다. 과거와 같은 결과를 재현하려면 보존된 당시 스냅샷을 사용한다. 393개 확대 수집은 40개 이하 묶음 10개를 순서대로 호출하고 결과를 합쳤다. 현재 CLI 한 번의 상한은 40개이므로 확대 목록을 그대로 단일 호출에 넘기지 않는다.
